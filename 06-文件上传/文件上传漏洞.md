# 文件上传漏洞

应用对上传文件的校验不严，导致攻击者可以上传恶意脚本或可执行程序，从而在服务器上执行任意代码。

## 一、漏洞产生原因

| 编号 | 原因 | 原理 |
| --- | --- | --- |
| 1 | 只校验文件后缀 | 仅凭扩展名黑名单（如 `php`、`jsp`）判断，容易被变形后缀绕过 |
| 2 | 只校验 MIME 类型 | 后端仅检查 HTTP 请求头中的 `Content-Type` 字段而非文件本身 |
| 3 | 上传目录可执行 | 上传的文件被保存在了 Web 服务器配置了的目录下，脚本可直接被解析执行 |
| 4 | 文件内容检测缺失 | 没有对文件的真实内容进行检测，伪装文件可顺利落盘 |
| 5 | 服务器解析规则存在问题 | 利用了 Web 服务器（如 Apache、Nginx）自身的解析特性与漏洞 |

## 二、常见绕过方式

1. **文件名 / 后缀绕过**：修改文件名，绕过扩展名限制
2. **MIME 绕过**：修改请求中的 `Content-Type`，绕过前端和后端的检测
3. **内容检测绕过**：在文件中插入合法内容（如 GIF89a 文件头），绕过文件类型检测
4. **目录解析绕过**：利用服务器解析规则，让文件被当作脚本执行

### 补充：MIME 类型是怎么来的？

当你通过浏览器上传文件时，浏览器会读取你选择的文件的后缀名，然后根据后缀名自动生成一个 `Content-Type` 塞进 HTTP 请求头里。

- 文件类型与文件后缀名没有关系
- 文件头属于文件内容
- 内容检测一般指的是检测文件头

## 三、攻击流程

1. 攻击者准备恶意脚本
2. 上传文件，绕过校验
3. 文件进入服务器可访问目录
4. 攻击者通过浏览器访问上传的文件
5. 服务器执行恶意代码，攻击者获得控制权限

## 四、防御措施

1. 使用扩展名白名单，而不是黑名单
2. 校验文件真实内容（如校验文件头）
3. 上传目录禁止脚本执行权限（`php_flag engine off` 等）
4. 重命名上传文件（随机文件名 + 白名单后缀）
5. 限制文件大小，拒绝服务器无法承受的大文件（如压缩包炸弹）
6. 部署 WAF 防护
